# 菜单管理 API 开发任务

## 一、目标

基于 `custom_menu` 表，实现完整的菜单管理后端 API。

菜单主要用于：

1. 后台配置导航菜单
2. 菜单可以关联自定义对象
3. 前台根据菜单配置动态生成导航栏
4. 支持目录菜单和对象菜单
5. 支持菜单新增、编辑、删除、启用/禁用、显示/隐藏、排序
6. 暂时不实现权限、角色、数据范围

API 统一使用：

```text
/api/v1
```

---

# 二、菜单类型

`menu_type` 支持：

```text
DIRECTORY   目录
OBJECT      自定义对象
LINK        外部/普通链接
```

### DIRECTORY

目录菜单，不关联对象。

例如：

```json
{
  "menuName": "自定义对象",
  "menuType": "DIRECTORY"
}
```

### OBJECT

自定义对象菜单，必须关联：

```text
objectApiName
```

例如：

```json
{
  "menuName": "项目",
  "menuType": "OBJECT",
  "objectApiName": "project__c"
}
```

### LINK

普通链接，可以配置：

```text
routePath
target
```

# 四、查询菜单树

```http

```

用途：

只返回：

```text

visible = 1
```

并按照：

```text

```

排序。

返回树结构：

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "id": 1,
      "parentId": 0,
      "menuName": "自定义对象",
      "menuType": "DIRECTORY",
      "icon": "Folder",
      "sort": 100,
      "children": [
        {
          "id": 2,
          "parentId": 1,
          "menuName": "项目",
          "menuType": "OBJECT",

          "routePath": "/custom/project__c",
```

注意：

前台接口不需要返回后台管理不需要的数据，可以返回完整菜单 DTO，也可以单独定义 `MenuTreeVO`。

# 八、删除菜单

```http
DELETE /api/v1/menus/{id}
```

示例：

```http
DELETE /api/v1/menus/2
```

返回：

```json
{
  "code": 200,
  "message": "菜单删除成功"
}
```

### 删除规则

如果删除的是 `DIRECTORY`：

需要检查是否存在子菜单。

如果存在子菜单：

```text
禁止删除
```

返回业务错误：

```json
{
  "code": 400,
  "message": "该菜单存在子菜单，请先删除子菜单"
}
```

如果没有子菜单，可以删除。

如果删除的是普通对象菜单：

直接删除。

# 十三、Object 菜单校验

创建：

```text
menuType = OBJECT
```

时：

```text
objectApiName
```

必须存在。

例如：

```json
{
  "menuName": "项目",
  "menuType": "OBJECT",
  "objectApiName": "project__c"
}
```

后端需要检查：

```text
project__c
```

对应的自定义对象是否存在。

如果不存在：

```json
{
  "code": 400,
  "message": "关联的自定义对象不存在：project__c"
}
```

注意：

数据库层面**不要建立外键**。

这是应用层校验。

# 十五、菜单树构建规则

数据库是扁平结构：

```text
id
parent_id
```

例如：

```text
1  自定义对象    parent=0
2  项目          parent=1
3  客户          parent=1
4  销售          parent=0
5  销售订单      parent=4
```

接口返回：

```json
[
  {
    "id": 1,
    "menuName": "自定义对象",
    "children": [
      {
        "id": 2,
        "menuName": "项目"
      },
      {
        "id": 3,
        "menuName": "客户"
      }
    ]
  },
  {
    "id": 4,
    "menuName": "销售",
    "children": [
      {
        "id": 5,
        "menuName": "销售订单"
      }
    ]
  }
]
```

使用 Java 内存构建树即可。

不需要递归查询数据库。

# 十八、接口总览

最终实现：

| Method | API                          | 用途     |
| ------ | ---------------------------- | ------ |
| GET    | `/api/v1/menus`              | 后台菜单列表 |
| GET    | `/api/v1/menus/tree`         | 前台菜单树  |
| GET    | `/api/v1/menus/{id}`         | 菜单详情   |
| POST   | `/api/v1/menus`              | 新增菜单   |
| PUT    | `/api/v1/menus/{id}`         | 修改菜单   |
| DELETE | `/api/v1/menus/{id}`         | 删除菜单   |
| PUT    | `/api/v1/menus/{id}/status`  | 启用/禁用  |
| PUT    | `/api/v1/menus/{id}/visible` | 显示/隐藏  |
| PUT    | `/api/v1/menus/{id}/sort`    | 修改排序   |
| PUT    | `/api/v1/menus/{id}/move`    | 移动菜单   |

# 二十、开发原则

这是 Demo，但代码结构必须为后续扩展保留空间。

暂时不实现：

```text
权限
角色
数据权限
用户权限
组织权限
菜单授权
```

但是数据库和 API 不要把这些逻辑写死。

重点是：

> **Menu Metadata → Frontend Navigation → Object Runtime**

三个部分真正打通。

完成后运行：

```bash
mvn clean test
```

确认项目可以正常编译和测试。
