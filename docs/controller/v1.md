# Object Engine V1 API 接口规范

## 1. 项目定位

Object Engine 是一个基于 **Metadata-Driven Architecture（元数据驱动架构）** 的动态业务对象引擎。

系统允许管理员在后台配置：

```text
对象
  ↓
字段
  ↓
字段类型
  ↓
字段属性
```

前端根据 Metadata 动态渲染：

```text
动态表单
动态列表
```

后端提供通用 CRUD：

```text
Object CRUD
Field CRUD
Record CRUD
```

---

# 2. API 版本

所有 API 必须使用版本前缀：

```text
/api/v1
```

完整路径示例：

```text
/api/v1/custom-objects
/api/v1/custom-objects/project__c/fields
/api/v1/objects/project__c/metadata
/api/v1/objects/project__c/records
```

禁止出现：

```text
/api/custom-objects
/api/objects/xxx
```

## 已实现

# 6. Object API

Object 表：

```text
custom_object
```

---

## 6.1 创建对象

```http
POST /api/v1/custom-objects
```

Request：

```json
{
  "apiName": "project__c",
  "objectName": "项目",
  "description": "项目管理对象",
  "remark": "项目基础信息",
  "icon": "project",
  "sort": 1
}
```

字段：

| 参数          | 类型      | 必填 | 说明     |
| ----------- | ------- | -: | ------ |
| apiName     | String  |  是 | API 名称 |
| objectName  | String  |  是 | 对象名称   |
| description | String  |  否 | 描述     |
| remark      | String  |  否 | 备注     |
| icon        | String  |  否 | 图标     |
| sort        | Integer |  否 | 排序     |

规则：

```text
apiName 必须唯一
apiName 创建后不可修改
objectName 不能为空
```

`apiName` 建议格式：

```text
project__c
customer__c
contract__c
```

---


```http

```

```json
{
  "objectName": "项目管理",

  "remark": "修改后的备注",
```

```text

```

---

## 6.5 删除对象

```http
DELETE /api/v1/custom-objects/{apiName}
```

例如：

```http
DELETE /api/v1/custom-objects/project__c
```

删除必须使用事务：

```text
删除 Object
    ↓
删除 Fields
    ↓
删除 Records
    ↓
删除 Object
```

因为数据库没有外键，所以由 Service 层维护。

# 8. Field Type

V1 只支持：

```text
TEXT
TEXTAREA
NUMBER
MONEY
DATE
SELECT
```

映射：

| Field Type | 说明   | Element Plus     |
| ---------- | ---- | ---------------- |
| TEXT       | 单行文本 | ElInput          |
| TEXTAREA   | 多行文本 | ElInput textarea |
| NUMBER     | 数字   | ElInputNumber    |
| MONEY      | 金额   | ElInputNumber    |
| DATE       | 日期   | ElDatePicker     |
| SELECT     | 下拉选择 | ElSelect         |

不要自行增加字段类型。

# 11. 修改字段

```http
PUT /api/v1/custom-objects/{apiName}/fields/{fieldApiName}
```

例如：

```http
PUT /api/v1/custom-objects/project__c/fields/name
```

Request：

```json
{
  "fieldName": "项目名称",
  "description": "项目名称",
  "remark": "项目名称备注",
  "requiredFlag": 1,
  "uniqueFlag": 0,
  "searchableFlag": 1,
  "sortableFlag": 1,
  "sort": 1,
  "defaultValue": null,
  "configJson": null,
  "status": 1
}
```

禁止修改：

```text
fieldApiName
fieldType
```

### 为什么 Field Type V1 也不允许修改？

因为：

```text
TEXT
    ↓
NUMBER
```

这种变化可能导致已有 JSON 数据无法正确解析。

V1 直接禁止。

如果未来需要修改字段类型，再单独设计数据迁移机制。

# 12. 删除字段

```http
DELETE /api/v1/custom-objects/{apiName}/fields/{fieldApiName}
```

例如：

```http
DELETE /api/v1/custom-objects/project__c/fields/status
```

删除 Metadata 即可。

不要修改历史 Record 的：

```text
data_json
```

例如原数据：

```json
{
  "name": "项目A",
  "amount": 10000,
  "status": "processing"
}
```

删除 `status` 后：

```json
{
  "name": "项目A",
  "amount": 10000,
  "status": "processing"
}
```

仍然可以存在。

但当前 Metadata 没有 `status`，所以前端不再显示。

# 14. Record API

数据库：

```text
custom_record
```

---

## 14.1 创建记录

```http
POST /api/v1/objects/{apiName}/records
```

例如：

```http
POST /api/v1/objects/project__c/records
```

Request：

```json
{
  "name": "测试项目",
  "amount": 100000,
  "status": "processing",
  "start_date": "2026-08-29"
}
```

注意：

Record 请求体直接使用：

```text
fieldApiName -> value
```

不需要：

```json
{
  "data": {
    "name": "测试项目"
  }
}
```

---

## 14.2 Record 创建校验

后端必须先读取：

```text
Object Metadata
       ↓
Field Metadata
       ↓
Validate Request
       ↓
Save Record
```

必须校验：

### 字段是否存在

如果请求：

```json
{
  "unknown_field": "xxx"
}
```

直接返回 400。

---

### required

字段：

```text
requiredFlag = 1
```

但请求缺失：

```json
{}
```

返回：

```json
{
  "code": 400,
  "message": "字段【项目名称】不能为空",
  "data": null
}
```

---

### Field Type

例如：

```text
amount = MONEY
```

但是：

```json
{
  "amount": "abc"
}
```

必须返回 400。

---

### SELECT

如果：

```text
status
```

只有：

```text
pending
processing
completed
```

请求：

```json
{
  "status": "hello"
}
```

必须拒绝。

# 18. 数据模型

数据库只有：

```text
custom_object
custom_field
custom_record
```

关系：

```text
custom_object
      │
      ├── custom_field
      │
      └── custom_record
```

数据库：

**禁止使用 Foreign Key。**

关系由 Java Service 层维护。

---

# 19. Object 删除事务

删除：

```text
DELETE /api/v1/custom-objects/project__c
```

必须：

```text
@Transactional
```

执行：

```text
1. 查询 Object
2. 删除 custom_field
3. 删除 custom_record
4. 删除 custom_object
```

任何一步失败：

```text
ROLLBACK
```

---

# 20. Record 数据格式

数据库：

```text
custom_record.data_json
```

例如：

```json
{
  "name": "测试项目",
  "amount": 100000,
  "status": "processing",
  "start_date": "2026-08-29"
}
```

JSON 的 Key 必须使用：

```text
field.apiName
```

而不是：

```text
field.fieldName
```

例如：

正确：

```json
{
  "amount": 100000
}
```

错误：

```json
{
  "项目金额": 100000
}
```


```text

       ↓
```

```text
       ↓
5. 根据 fields 渲染 Form
       ↓

       ↓

       ↓

   ↓
```

```text
   ↓

   ↓
```

# 26. 核心设计原则

### 1. Object API Name 永久稳定

```text
project__c
```

创建后不能修改。

---

### 2. Field API Name 永久稳定

```text
amount
```

创建后不能修改。

---

### 3. Field Type V1 不允许修改

例如：

```text
amount: MONEY
```

不能直接改成：

```text
amount: TEXT
```

---

### 4. 前端不能写死业务对象

前端只认识：

```text
Metadata
FieldType
```

不知道：

```text
Project
Customer
Contract
```

---

### 5. 后端不能写业务对象 Service

禁止：

```text
ProjectService
CustomerService
ContractService
```

动态对象统一使用：

```text
CustomRecordService
```

---

### 6. 数据库不建立外键

关系由 Service 管理。

---

### 7. 不要提前实现未来功能

V1 目标只有：

```text
配置 Object
       ↓
配置 Field
       ↓
获取 Metadata
       ↓
动态 Form
       ↓
动态 Table
       ↓
Record CRUD
```

---

# 27. V1 最终验收

必须完整跑通：

```text
创建对象
    ↓
project__c / 项目
    ↓
创建字段
    ↓
name / 项目名称 / TEXT
amount / 项目金额 / MONEY
status / 项目状态 / SELECT
start_date / 开始日期 / DATE
    ↓
打开 /custom/project__c
    ↓
GET Metadata
    ↓
自动生成列表
    ↓
点击新建
    ↓
自动生成表单
    ↓
填写数据
    ↓
POST Record
    ↓
列表出现数据
    ↓
点击删除
    ↓
DELETE Record
    ↓
列表刷新
```

最终验证：

**不修改 Java 业务代码、不修改 Vue 业务页面、不修改数据库表结构，仅通过后台新增 Object / Field，就可以创建出新的动态业务对象。**

例如随后创建：

```text
customer__c
```

配置：

```text
客户名称
客户电话
客户等级
```

系统应该自动得到：

```text
/custom/customer__c
```

并自动拥有：

```text
列表
新建
表单
删除
分页
```

这就是 Object Engine V1 的核心验收标准。
