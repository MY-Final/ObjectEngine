# Git 提交规范

本仓库所有 commit 必须遵循以下格式。

## 格式

```
<type>: 中文描述

- 正文
- 正文
```

规则：

1. 标题行：`type: 中文描述`——type 小写，冒号后跟一个空格，描述用中文，结尾不加句号，尽量不超过 50 字。
2. 标题行与正文之间**空一行**（否则 git 会把正文折叠进标题）。
3. 正文：每行以 `- ` 开头，一条一个要点，说清楚改了什么、为什么改。琐碎改动可以只有标题、省略正文。
4. 一次 commit 只做一件逻辑上独立的事；不要把不相关的改动混在一个 commit 里。

## type 取值

| type     | 用途                         |
| -------- | ---------------------------- |
| feat     | 新功能                       |
| fix      | 缺陷修复                     |
| refactor | 重构（不改变行为）           |
| docs     | 文档                         |
| test     | 测试                         |
| build    | 构建 / 依赖（如 pom.xml）    |
| chore    | 杂项（配置、脚本等）         |
| perf     | 性能优化                     |
| ci       | CI 配置                      |

## 示例

本仓库首次提交（de2a07a）即标准示例：

```
feat: 初始化 Spring Boot 项目并接入 MySQL 数据源

- 补充 Web/JPA/Validation 依赖，替换原有裸 starter
- 配置数据源连接 192.168.2.9:33306/object 及 Hikari 连接池
- 配置 JPA（ddl-auto: none）与服务端口 8080
- 通过 mvnw test 验证构建与数据库连通性
```
